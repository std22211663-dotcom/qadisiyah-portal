# بوابة تربية القادسية الإلكترونية — نسخة الخادم (2.0.0)

نسخة كاملة من البوابة تعمل على خادم حقيقي مع قاعدة بيانات، بدلاً من حفظ البيانات في متصفح كل جهاز.

## ما الذي تغيّر عن النسخة السابقة

| | النسخة السابقة (Artifact) | نسخة الخادم |
|---|---|---|
| مكان البيانات | متصفح كل جهاز على حدة | قاعدة بيانات واحدة على الخادم (SQLite) |
| المراجع والإدارة والأقسام | يجب أن يكونوا على الجهاز نفسه | كل واحد من جهازه، والبيانات مشتركة |
| كلمات المرور | محفوظة كما هي | مشفّرة (scrypt) |
| الصلاحيات | تُفحص في المتصفح فقط | تُفحص في الخادم لكل إجراء |
| المرفقات | يُحفظ اسم الملف فقط | يُحفظ الملف نفسه ويُفتح من التفاصيل |
| الطباعة | تحميل نسخة للطباعة | طباعة مباشرة من زر «طباعة» |
| التحديث | داخل المتصفح نفسه فقط | تلقائي كل 15 ثانية لكل المستخدمين |

## الميزات الحالية

- **المراجع:** إنشاء حساب (مع الرقم الوظيفي ورقم الهوية)، تقديم طلب بتوقيع ومرفقات، طلب مقابلة، متابعة الطلب، وصفحة **«معلوماتي»** لعرض بياناته وتعديلها وتغيير كلمة المرور.
- **الدخول عند نسيان كلمة المرور:** تبويب «الرقم الوظيفي»، والتحقق بتاريخ التولد أو رقم الهوية. يُقفل الحساب والجهاز 5 دقائق بعد 5 محاولات خاطئة.
- **منع تكرار الحساب:** لا يُسمح بحسابين بنفس اسم المستخدم أو الهاتف أو الرقم الوظيفي أو رقم الهوية، ولا بنفس الاسم وتاريخ التولد.
- **الإدارة:** الموافقة والرفض، الهامش والتحويل للأقسام، حسابات الأقسام والشعب، إدارة المستخدمين، **إدارة المراجعين مع إضافتهم وتعديلهم**، سجل النشاطات، المحذوفات، النسخ الاحتياطي.
- **الدعم الفني:** زر في صفحة الدخول يرسل منه المستخدم (حتى بدون حساب) اسمه ومكان عمله وعنوانه الوظيفي وشرح مشكلته وصورة اختيارية، وتظهر للمدير في صفحة **«المشاكل المرسلة»** مع عدّاد للجديد.
- **التصميم:** واجهة عربية بألوان زرقاء وزمردية وذهبية مع زجاج شفاف وانعكاسات، وزر **الوضع الداكن/الفاتح** في أعلى كل الصفحات، وتاريخ ووقت بقوائم عربية.

## المتطلبات

- **Node.js الإصدار 22.13 أو أحدث** (يُنصح بإصدار LTS من https://nodejs.org).
- لا يحتاج تثبيت أي مكتبات (`npm install` غير مطلوب)؛ قاعدة البيانات SQLite مدمجة في Node.js.
- اتصال إنترنت على أجهزة المستخدمين لتحميل الخط (Cairo) ومكتبات PDF وExcel من الإنترنت. بدون إنترنت تعمل البوابة، لكن تحميل PDF واستيراد ملفات xlsx لا يعملان (ملفات CSV تعمل).

## التشغيل

```bash
node server.js
```

في Windows: انقر مرتين على `start.bat`.

ثم افتح: http://localhost:3000

> إذا كان المنفذ 3000 مشغولاً بمشروع آخر فشغّل البوابة على منفذ ثانٍ: `PORT=3001 node server.js` (في PowerShell: `$env:PORT=3001; node server.js`). وبعد أي تعديل على `server.js` أعد تشغيل الخادم.

## الاختبار

```bash
npm test
```
يشغّل 103 فحصاً في نحو 8 ثوانٍ، وكل مجموعة تعمل على خادم وقاعدة بيانات مؤقتين، ولا يلمس مجلد `data/` الحقيقي.

**الحساب الافتراضي عند أول تشغيل:** `admin` / `Admin@123` — **غيّر كلمة المرور فوراً** من الإعدادات ← تغيير كلمة المرور.
لتعيين كلمة مرور أخرى عند أول تشغيل: `ADMIN_PASSWORD="كلمة-قوية" node server.js`

## الإعدادات (متغيرات البيئة)

| المتغير | الافتراضي | الوصف |
|---|---|---|
| `PORT` | `3000` | منفذ الخادم |
| `HOST` | `0.0.0.0` | استخدم `127.0.0.1` إذا كان خلف nginx |
| `DATA_DIR` | `./data` | مكان قاعدة البيانات والمرفقات |
| `ADMIN_PASSWORD` | `Admin@123` | كلمة مرور المدير العام عند أول تشغيل فقط |
| `SESSION_DAYS` | `7` | مدة بقاء تسجيل الدخول |
| `TRUST_PROXY` | — | ضع `1` إذا كان الخادم خلف nginx أو وكيل |
| `COOKIE_SECURE` | — | ضع `1` عند استخدام HTTPS (مطلوب في الاستخدام الفعلي) |

## نقل البيانات من النسخة السابقة

1. في البوابة القديمة: الإعدادات ← النسخ الاحتياطي والحذف ← «تصدير نسخة احتياطية».
2. في نسخة الخادم: سجّل الدخول بحساب المدير ← الإعدادات ← النسخ الاحتياطي والحذف ← اختر الملف ← «استعادة هذه النسخة».

تنتقل الحسابات والطلبات والمقابلات والسجلات، وتُشفّر كلمات المرور القديمة تلقائياً، فيدخل كل مستخدم بكلمة مروره السابقة.
ملاحظة: المرفقات القديمة لم تكن محفوظة أصلاً في النسخة السابقة، لذلك يظهر اسمها فقط.

## النشر على خادم المديرية

**خادم Linux (موصى به):**
1. انسخ المجلد إلى `/opt/qadisiyah-portal` وأنشئ مستخدماً للنظام اسمه `portal`.
2. استخدم ملف `deploy/qadisiyah-portal.service` لتشغيل البوابة تلقائياً مع الخادم.
3. استخدم `deploy/nginx.conf` لوضع nginx أمامها مع شهادة HTTPS (certbot).

**خادم Windows:** شغّل `start.bat`، أو استخدم أداة مثل NSSM لتشغيله كخدمة Windows، وافتح المنفذ في جدار الحماية.

**خدمات الاستضافة (Render / Railway وغيرها):** أمر التشغيل `node server.js`، واجعل `DATA_DIR` على قرص دائم (Persistent Disk)، وإلا تُمسح البيانات عند إعادة التشغيل.

## النسخ الاحتياطي

- كل البيانات في مجلد `data/`: الملف `portal.db` ومجلد `uploads/` (المرفقات).
- انسخ مجلد `data/` كاملاً يومياً إلى مكان آخر، أو استخدم «تصدير نسخة احتياطية» من الإعدادات (يشمل الحسابات والطلبات والمقابلات ورسائل الدعم الفني، ولا يشمل ملفات المرفقات والصور).

## الأمان

- كلمات المرور مشفّرة، والجلسات بكوكيز HttpOnly، وكل إجراء يُفحص بصلاحيات الحساب على الخادم.
- 5 محاولات دخول خاطئة توقف المحاولة 5 دقائق، ويسري ذلك أيضاً على الدخول بالرقم الوظيفي (قفل للجهاز وللحساب).
- الدخول بالرقم الوظيفي أضعف من كلمة المرور لأن تاريخ التولد قابل للتخمين، لذلك هو للمراجعين فقط ولا يفتح حسابات الإدارة، وتغيير الرقم الوظيفي أو الهوية أو التولد يتطلب كلمة المرور الحالية.
- رسائل الدعم الفني: 5 رسائل في الساعة لكل جهاز، وصورة واحدة، ولا يراها إلا من يملك صلاحية إدارة المستخدمين.
- كل حساب يستلم من الخادم ما تسمح به صلاحياته فقط؛ المراجع لا يرى إلا طلباته، وحساب القسم لا يرى إلا الطلبات المحوّلة إليه.
- استخدم HTTPS دائماً في الاستخدام الفعلي، ولا تشارك مجلد `data/`.

## هيكل المشروع

```
server.js          الخادم: قاعدة البيانات، الصلاحيات، الواجهة البرمجية، الملفات
org.json           الهيكل التنظيمي: المدير العام والمعاونان والأقسام والشعب
public/index.html  واجهة البوابة
test/              فحوصات النظام (npm test)
deploy/            أمثلة إعداد systemd وnginx
data/              (يُنشأ تلقائياً) قاعدة البيانات والمرفقات
```

لتعديل الأقسام أو الشعب عدّل `org.json` ثم أعد تشغيل الخادم. `"acc": true` تعني أن القسم أو الشعبة لها حساب في النظام.
